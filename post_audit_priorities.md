# Post-Audit Priority Backlog

The latest audit pass is complete, so there are **no remaining essential tasks required to count the current UX fix round as finished**. What remains is a **post-audit polish backlog**. The right framing now is not "unfinished core work" but "what should be improved next to reduce future friction and improve conversion confidence".

## Priority summary

| Tier | What it means now | Recommended focus |
|---|---|---|
| Critical next fixes | Not blockers for the completed audit pass, but the most valuable next work because they reduce repeat regressions or confusion in high-traffic flows | Do these next if you want the safest product improvement step |
| Worthwhile improvements | Strong improvements to perceived polish, conversion confidence, and clarity, but not urgent for basic usability | Do these after the critical fixes |
| Optional enhancements | Useful upgrades once the product direction is stable, especially if you want stronger premium positioning | Do these when you want additional marketing strength rather than friction reduction |

## Recommended backlog

| Tier | Item | Why it belongs here |
|---|---|---|
| Critical next fixes | **Stabilize CTA logic by audience state across public pages** | The audit explicitly flagged CTA inconsistency across visitor, signed-in, and dashboard-entry states. The new dashboard gate is fixed, but the broader CTA model can still be made more consistent across home, pricing, FAQ, and subscriber flows. This matters because CTA ambiguity affects conversion and user confidence directly. |
| Critical next fixes | **Formalize the mobile design system for public headers, drawer behavior, and internal page headers** | The user has already experienced repeated mobile regressions. The visible bugs are addressed, but the stronger long-term fix is to consolidate these patterns so future edits do not reintroduce spacing, navigation, or header inconsistencies. |
| Worthwhile improvements | **Add more concrete in-product preview examples on the homepage** | The homepage now explains the workflow more clearly, but it would convert better if users could see stronger product proof such as sample signal cards, confidence examples, or mini dashboard previews. |
| Worthwhile improvements | **Deepen trust content with clearer methodology and data-freshness cues** | Trust has improved, but a premium trading product usually benefits from more explicit cues around how rankings work, how often data updates, and how users should interpret confidence. |
| Worthwhile improvements | **Refine plan differentiation messaging further through outcome-based copy** | Pricing clarity is much better, but it can still become more decision-oriented by tying each tier more explicitly to user type, workflow depth, and expected usage frequency. |
| Optional enhancements | **Create a richer guided product story using annotated screenshots or a more produced walkthrough asset** | The walkthrough framing is stronger now, so this is no longer essential. It becomes most valuable if you want a more persuasive public marketing layer. |
| Optional enhancements | **Add customer proof or usage credibility once real evidence is available** | This would help premium positioning, but it should only be added when you have authentic testimonials, track records, or validation outputs worth showing. |
| Optional enhancements | **Extend the public information architecture with dedicated methodology or responsible-use pages** | Useful for trust and SEO, but not necessary for the current product flow to function well. |

## My recommendation

If you want the **safest next sprint**, I would treat two items as the best next work: first, the **shared CTA logic by audience state**; second, the **formalized mobile design system and shared header/navigation rules**. Those two are the highest-leverage follow-ups because they reduce the chance of future regressions and improve the consistency users feel across the most visible journeys.

If instead you want the **best conversion-oriented sprint**, then after those two, I would move to **homepage product proof examples** and **deeper trust/methodology cues**.
